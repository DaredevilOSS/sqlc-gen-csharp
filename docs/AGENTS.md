# docs/AGENTS.md

`README.md` at the repo root is **generated**: `cat docs/0*.md > README.md` (`docs/scripts/generate_all_docs.sh`).
Edit the files in `docs/`, never `README.md`.

| File                 | How it is maintained |
|----------------------|----------------------|
| `01_Intro.md`, `03_Usage.md`, `04_Postgres.md`, `05_MySql.md`, `06_Sqlite.md`, `07_Benchmark.md`, `08_Contributing.md` | hand-written |
| `02_Quickstart.md`   | generated by `docs/scripts/generate_quickstart.sh` (latest release tag + wasm sha256; downloads from GitHub) |
| `09_Examples.md`     | generated from `sqlc.ci.yaml` by `docs/ExamplesDocGen` |

## README is updated by the release flow
`gen-release-pr.yml` runs `generate_all_docs.sh` with the new version and wasm sha and opens the `release-prep` PR.
A manual `docs.yml` workflow (`workflow_dispatch`) does the same against the latest release and opens an
`update-docs` PR. Those two workflows are the only places `README.md` and `02_Quickstart.md` should change. In a feature PR:
- edit the hand-written `docs/*.md` files;
- if `sqlc.ci.yaml` changed, regenerate `09_Examples.md`:
  `dotnet run --project docs/ExamplesDocGen/ExampleDocGen.csproj > docs/09_Examples.md`;
- do **not** regenerate `README.md` / `02_Quickstart.md` (it would pin the previous release).

So `README.md` normally lags behind `docs/` until the next release - that is expected.

## What to keep in sync with the code
| Code                                              | Doc |
|---------------------------------------------------|-----|

| A driver's `ColumnMappings`                       | "Supported Data Types" table in `04_Postgres.md` / `05_MySql.md` / `06_Sqlite.md` |
| `:execlastid` / `:copyfrom` implementation        | the implementation `<details>` sections in the same files |
| Annotation / macro support                        | tables in `03_Usage.md` |
| Build / test / WASM tooling                       | `08_Contributing.md` |
